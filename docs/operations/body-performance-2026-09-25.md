# 전신 트윈 성능 프로파일 — 2026-09-25

대상 소스: `24b154c3162de5c145807d6d02d26103567c8d4b`. 이번 작업은 진단이며 애플리케이션 렌더링·모델·기본 옵션을 변경하거나 배포하지 않았다.

## 측정 범위와 재현

Apple M4 Pro, macOS arm64, Chrome 153.0.8010.49 headless, ANGLE Metal 하드웨어 렌더러. 실제 `AnatomyScene`을 esbuild로 번들링하여 독립 화면에서 실행했다. 모델 로딩, 변형 셰이더, 물리, 모션은 실제 코드를 사용한다. React 패널과 파형은 포함하지 않는다. 따라서 전체 페이지의 종합 프로파일이나 저사양 랩탑 재현으로 해석하면 안 된다.

3D 영역은 CSS 1000×850px. 기본 DPR 1.5를 유지하고 자동 DPR 하향만 측정 중 비활성화했다. 조건별 1.8초 준비 후 3.5초, 약 210프레임을 수집했다. GPU 시간은 `EXT_disjoint_timer_query_webgl2`의 비동기 쿼리이며 CPU의 `renderer.render()` 호출 시간과 구분한다. 로컬 HTTP 모델 전송이므로 인터넷 다운로드 시간은 대표하지 않는다. 신경 바인딩 시간은 실제 `NerveSkinGuard.bind()`의 모든 호출 합계다.

```sh
node scripts/profiling/body-profile.mjs
```

웹 프로젝트 루트에서 실행한다. Chrome 기본 위치는 macOS이며 다른 환경은 `CHROME_PATH`로 실행 파일을 지정한다. 기존 브라우저와 분리된 임시 프로필을 사용하고 종료 시 제거한다. 재현 스크립트는 `scripts/profiling/body-profile.mjs`, 브라우저 측 계측은 `scripts/profiling/body-browser.ts`, 결과 JSON은 `outputs/profiling/body-profile.json`에 저장한다. outputs는 Git 제외 대상이다.

단계 시간에는 요청·디코딩·동기 전처리와 그 사이의 브라우저 작업이 포함된다. 신경 바인딩 약 5.39초는 전체 경과 시간의 약 56%이며, 메인 스레드에서 정점마다 피부의 최근접 삼각형·내외부·부착 좌표를 계산한다. 이 부분의 사전 계산이 초기 응답성 개선의 가장 확실한 대상이다. 이 수치를 그대로 로딩 단축 보장치로 사용하지 않는다.

두 번째 실행 결과. GPU 시간은 중앙값 / p95, 단위 ms. 레이어 제외 비교에서는 다른 기본값을 유지했다.

모든 조건에서 rAF 간격 중앙값 약 16.7ms로 60Hz 제한에 도달했다. 이 컴퓨터에서는 사용자가 겪는 저FPS를 재현하지 못했다. 짧은 순차 비교이며 GPU 클록·전력 상태·포즈 변화가 통제되지 않았다. 일시정지가 더 비싸다는 인과관계나 다른 기기에서의 개선율을 주장하지 않는다. 확인되는 사실은 일시정지에도 동일한 삼각형을 계속 렌더링한다는 점이다.

기본 걷기 CPU 구간 중앙값 / p95: 조직 물리 0.40 / 1.40ms, 본 업데이트 0.10 / 0.20ms, 피부 본 복사 약 0 / 0.10ms, 렌더 명령 제출 0.30 / 0.80ms. 브라우저 타이머 해상도로 0에 반올림된 값은 무비용을 뜻하지 않는다. 첫 실행에서는 물리 중앙값 1.10ms, 본 0.20ms였다. 이 구간은 모든 프레임 CPU 작업을 포함하지 않으며 GPU 시간과 단순 합산하지 않는다.

## 코드로 확인한 비용과 해석

- 기본 레이어는 순환계 100%, 내장 80%, 신경 65%, 골격 13%, 근육 9%다. 9% 투명도여도 근육의 약 77만 삼각형과 셰이더 계산이 실행된다. 반투명 중첩으로 픽셀 처리 비용도 추가될 수 있다.
- 이미 조직 종류별로 메시를 합치고 있어 draw call은 14회다. 추가 배칭은 최우선 해결책이 아니다.
- 신경 정점 약 36만 개에 피부 삼각형 3개 정점의 변형을 다시 계산하는 보호 셰이더가 붙는다. 보호 계산 경로에서 텍스처 조회 12회, 추가 DQ 블렌딩, 조직 필드 샘플링 및 역행렬 계산이 발생한다. 이것은 소스 분석이며 개별 셰이더 명령의 GPU 비용 분해 측정은 아니다.
- DPR 1.5→1.0은 픽셀 수를 약 56% 줄이지만 이 측정에서는 GPU 시간 개선이 확인되지 않았다. 픽셀 수보다 정점 처리 부담이 큰 상황과 부합하나 확정 판정은 아니다.
- 조직 물리는 112개 노드, 120Hz 고정 서브스텝을 사용한다. 현재 측정에서는 모션 계산보다 무겁지만 이를 먼저 제거할 근거는 없다.
- 파형은 별도 rAF에서 약 30Hz로 전체 구간을 다시 합성한다. 본 계측에서는 제외했으므로 다중 센서 선택 시 전체 페이지 CPU 비용은 추가 검증해야 한다.

## 권장 순서

1. **신경 부착·조직 바인딩·혈관 연결을 빌드 시 사전 계산.** 피부 최근접 검색과 세분화 결과를 GLB 속성 또는 버전 연동 sidecar에 저장한다. 모델/리깅 변경 시 재생성한다. 초기 로딩 개선 근거가 가장 강하며 형태를 유지할 수 있다. 파일 크기 증가와 속성 압축 방식도 검증한다.
2. **전신 전용 LOD와 관심 부위 정밀 모델.** 저사양 전체 보기에는 총 50만~80만 삼각형을 초기 설계 목표로 삼고, 확대하거나 선택한 부위만 고해상도로 교체한다. 목표는 아직 검증하지 않은 제안이다. 혈관 연결, 신경 부착, 피부 감싸기, 폐/심장 경계, 센서 좌표를 보존해야 한다. 렌더 메시 단순화와 생리 신호 계산 모델은 분리한다.
3. **신경 보호 계산 공유.** 피부 정점의 변형 결과를 프레임마다 한 번 계산해 재사용하거나 국소 보호 영역·저해상도 경계로 계산량을 줄인다. 보정 자체를 끄면 기존 돌출 버그가 재발하므로 유지한다. 텍스처 쓰기/읽기 추가 비용과 WebGL 호환성을 비교한 후 채택한다.
4. **저사양 렌더링 프리셋.** 사용자 선택 레이어 중심으로 표시하고 근육/신경 동시 반투명 중첩을 줄인다. 동적 DPR 0.75~1.0, 선택적 MSAA, 30FPS 모드를 조합한다. DPR 단독보다 LOD와 조합할 필요가 있다. 현재 자동 조정은 저FPS가 이어질 때 DPR을 1로 내리는 것뿐이다.
5. **일시정지·비활성 화면은 변경 시에만 렌더링.** 카메라 조작·옵션 변경·리사이즈 때는 갱신하고, damping이 끝나면 렌더를 멈춘다. 배터리와 발열 개선이 주목적이며 재생 중 FPS를 올리는 방법과 구분한다.
6. **후순위 CPU 절약.** 동일 본 팔레트 재사용, 숨겨진 마커 계산 생략, 임시 배열 재사용, 파형 샘플 캐시/공유. 실제 저사양 기기에서 물리가 병목이면 물리 갱신률과 Worker를 검토하되 호흡 변형·접촉 안정성을 회귀 검증한다.

다음 검증은 대상 랩탑의 브라우저·해상도·하드웨어 가속 상태를 기록하고 전체 페이지에서 걷기/인사/춤, 센서 0개/다중 선택, 레이어 조합별로 최소 30초씩 반복한다. 프레임 간격 p95, GPU 시간, main-thread long task, 초기 로딩, 메모리를 비교한다. CPU 4배 제한은 저사양 GPU를 모사하지 못하므로 대체 수치로 쓰지 않는다.
