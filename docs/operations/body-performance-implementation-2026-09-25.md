# 전신 트윈 성능 개선 적용 — 2026-09-25

[기존 프로파일](body-performance-2026-09-25.md)의 권장 순서 1–6을 적용했다. 이전 프로파일은 당시 측정 기록으로 보존한다.

## 순서별 변경

1. `npm run build:body-assets`가 기존 전처리 경로에서 조직 바인딩, 혈관 연결, 신경 피부 부착을 사전 계산한다. 배포 모델은 meshoptimizer 무손실 속성 압축과 gzip으로 저장한다. 정수 본·피부 부착 ID를 양자화하지 않는다. 일반 빌드는 소스 지문을 확인하며 오래된 자산이면 중단한다. 베이킹에는 Chrome이 필요하고 다른 OS에서는 `CHROME_PATH`를 지정한다. 일반 설치·실행에는 Chrome 베이킹이 필요 없다.
2. 전신 경량 모델과 머리·몸통·양팔·다리의 정밀 모델을 분리한다. 균형 모드에서 카메라가 가까워지면 관심 영역만 정밀화하고 멀어지면 메모리를 해제한다. 고화질은 보이는 모든 영역을 정밀화한다. 원본 정점 위치와 속성을 유지하고 열린 경계를 고정하며, 외피·심장·폐·간은 감축하지 않는다. 신호 생성 모델은 변경하지 않는다.
3. 피부 변형 위치·법선·회전·이동을 GPU 텍스처에 한 번 계산하여 신경에서 재사용한다. 부동소수점 렌더 타깃 미지원 시 기존 보호 셰이더를 사용한다. 돌출 방지 보정은 유지한다. 신경을 숨기면 캐시 갱신을 생략한다.
4. 자동·저사양·균형·고화질을 추가했다. 자동은 논리 프로세서 ≤4 또는 브라우저 보고 메모리 ≤4GB이면 저사양, 그 외 균형으로 시작한다. 초기 측정 구간 뒤 3회 연속 초당 42프레임 미만이면 저사양으로 전환한다. 백그라운드·일시정지 시간은 판단에서 제외한다. 수동 선택은 자동 변경보다 우선하고 브라우저에 저장한다. 자동 상향은 하지 않는다.
5. 일시정지 후 카메라 damping이 끝나면 그리기를 멈춘다. 옵션·카메라·화면 크기 변경 시 다시 그린다. 숨겨진 탭의 3D 렌더링을 중단한다.
6. 피부와 내부 구조가 본 팔레트를 공유한다. 숨겨진 센서 마커 갱신을 생략하고, 같은 프레임·부위·시간의 파형 합성을 공유한다. 정지·숨겨진 파형은 다시 그리지 않는다. 물리의 120Hz 고정 서브스텝 및 CSV 샘플링은 유지한다.

| 모드 | DPR 상한 | 목표 FPS | 모델 |
| --- | ---: | ---: | --- |
| 저사양 | 0.85 | 30 | 전신 경량 |
| 균형 | 1.15 | 60 | 전신 경량 + 확대 영역 정밀 |
| 고화질 | 1.5 | 60 | 보이는 영역 정밀 |

FPS는 상한/목표이며 보장값이 아니다. 저사양으로 처음 시작할 때 근육·신경을 숨기고 사용자가 다시 켤 수 있다. 실행 도중 자동 하향할 때는 사용자의 레이어 선택을 유지한다. MSAA는 첫 컨텍스트 생성 시 저사양이면 끄며, 세션 중 모드 변경 시 컨텍스트를 재생성하지 않는다.

## 검증과 측정

Apple M4 Pro / macOS arm64 / Chrome 153 headless / ANGLE Metal, 로컬 HTTP, 1000×850 CSS 픽셀. 실제 AnatomyScene을 사용하되 React 패널을 제외했다. 비교 프로파일은 모드별 DPR 차이 외에는 1.5로 고정한다. 실제 기본 균형 모드의 DPR 상한은 1.15다. 전체 페이지나 저사양 랩탑의 결과로 해석하지 않는다.

- 최신 로컬 로드: **404ms**, 런타임 신경 부착 계산 **0ms**. 기존 기록은 **9.65–9.96초**. 로컬 전달·디코딩·준비 시간이며 인터넷 다운로드 개선율은 아니다.
- 기본 보이는 삼각형: **2,626,421 → 782,529**, 약 **70.2% 감소**. draw call은 영역 분할로 **14 → 44** 증가한다. 고화질 전환 후 원래 삼각형 수, 균형 복귀 후 경량 수를 확인했다.
- 기본 geometry attribute/index 배열: **70.19MiB**. 이전 기록은 174.02MiB. 전체 메모리나 VRAM 측정은 아니다.
- 초기 모델 다운로드: **17.10MiB**, 정밀 모델 추가 **36.14MiB**. 기존 GLB 11.39MiB보다 초기 전송은 늘어난다. CPU 계산을 파일로 옮기는 절충이다.
- 최신 GPU 중앙값: 균형 캐시 6.98ms, 균형 캐시 해제 5.89ms, 균형 재측정 4.53ms. 고화질 캐시 10.03ms, 해제 9.12ms. 이전 실행에서는 캐시가 더 빨랐으므로 순차 단회 결과만으로 보편적인 GPU 개선을 주장하지 않는다. 캐시 공유는 구현됐으나 기기별 효용 검증이 더 필요하다.
- 저사양 렌더는 3.5초 동안 본 업데이트 105회, 균형은 210회. 저사양 비교에서도 모든 초기 레이어를 유지한 스트레스 조건이다. rAF 간격은 스케줄러 간격이므로 30FPS 렌더를 60FPS로 오인하지 않는다.
- 일시정지 안정 구간 3.5초: 렌더·본·물리 갱신 **0회**.
- 인사·재즈·기준 자세에서 GPU 피부 캐시와 CPU 변형 위치 최대 차이 **0.000000532m**. native 외피/신경 피부 내부 유지, 어깨 연결, 침대·의자 접촉 및 LOD 속성 보존을 포함해 **148개 테스트 통과**.
- TypeScript 검사, 한·영 문서 생성 및 문서 무결성 검사 통과. 인사·재즈 외피/신경 캡처 확인.

재현: `node scripts/profiling/body-profile.mjs`. 결과는 Git 제외 경로 `outputs/profiling/body-profile.json`에 저장된다. `POSE_QA=1`을 지정하면 동작 캡처를 만든다. 모델 갱신 후 `npm run build:body-assets`, `npm test`, `npx tsc --noEmit --incremental false`, `npm run build` 순서로 검증한다.

남은 검증은 실제 저사양 랩탑에서 여러 레이어·센서 조합의 장시간 FPS·GPU 비용·발열을 측정하는 것이다. 자동 모드의 선택과 수동 재정의가 가능하며, 현재 수치로 해당 랩탑의 FPS를 보장하지 않는다.

## 수면·손목 화면 확장

수면 상단과 손목 카드 제목줄에 같은 모드 선택을 연결했다. `soma.body.quality` 저장값을 세 화면에서 공유한다. 별도 재생 루프도 공통 렌더 예산을 사용하며, 수면과 손목 아바타는 원래의 신호·자세 계산과 독립적으로 LOD·DPR·FPS를 적용한다. 손목 국소 구조는 유지하고 렌더 해상도·프레임 상한·그림자만 조절한다. 전극 설정·Worker 분석·샘플링 레이트는 변경하지 않았다. 손목 어댑터에서도 GPU 신경 캐시를 렌더 직전에 갱신한다.

실제 로컬 서버 브라우저 검증에서 `.gz` 응답에 Content-Encoding이 있으면 fetch가 이미 압축을 해제하는 문제가 확인되어, 파일의 gzip 헤더 유무를 판별하도록 디코더를 수정했다. 원본 압축/HTTP 해제 응답 모두 테스트한다. 손목 스크롤바의 기존 번역 import 별칭 오류도 함께 보정했다.

151개 테스트, TypeScript, 문서 검사 통과. `node scripts/profiling/simulator-quality-smoke.mjs`는 포트 3000의 로컬 앱에서 수면/손목을 실제 로드하고 세 모드와 저장값·런타임 오류를 검사한다. DPR 2 환경에서 수면 캔버스 CSS 991px의 실제 너비는 저사양 842 / 균형 1139 / 고화질 1486px, 손목 두 3D 캔버스 CSS 504px는 각각 428 / 579 / 756px였다. 이는 해상도 적용 확인이며 FPS 성능 개선율 측정은 아니다.
