# 수면무호흡 화면 전환 지연 분석

측정: 2026-09-25. 소스: 0ac0cc7. 기능 수정이나 재배포 없이 기존 production build와 배포 사이트를 검사했다.

## 측정

격리된 headless Chrome, 1400×1000, 로컬 생산 빌드 및 실제 배포 URL. 출발 화면에서 12초 대기한 뒤 실제 메뉴 링크를 클릭했다. 화면 표시는 `.sleep-anatomy` 생성, 모델 준비는 `.sleep-loading` 제거를 기준으로 한다. GPU 완전 안정화나 임상 신호 워밍업 완료를 의미하지 않는다. 폴링 오차 약 100ms이며 저사양 랩탑 측정은 아니다.

| 경로 | 로컬 화면/모델 준비 | 배포 화면/모델 준비 |
|---|---|---|
| 홈 → 수면 | 0.10 / 0.64초 | 0.31 / 2.39초 |
| 전신 → 수면 | 0.10 / 0.52초 | 0.24 / 1.76초 |
| 손목 → 수면 | 0.14 / 0.47초 | 3.76 / 6.03초 |

손목 경로 추가 2회: 3.54 / 5.59초, 0.24 / 1.97초. 따라서 손목에서 항상 6초가 걸리는 것은 아니다. 느린 두 경우 navigation responseStart가 약 2초였고 공통 JS 요청도 1.5초 이상 걸렸다. 네트워크/서버/브라우저 대기 중 정확한 원인은 이 기록만으로 분리할 수 없다. 특정 WebGL 정리 버그라고 단정하지 않는다.

## 확인된 원인

1. `app/simulator-nav.tsx`: 일반 a 링크로 문서 전체 이동. WebGL 수명 관리를 위한 의도적인 구현이지만 JS 실행 상태, 디코딩한 모델, GPU 자원을 다시 준비한다. SPA 전환으로 바꾸려면 iframe, RAF, worker, renderer의 정리를 먼저 보장해야 한다.
2. `lib/anatomy.ts`의 `load`: 43개 모델을 for/await로 순차 fetch → 압축 해제 → Meshopt 디코딩 → 메시 생성한다. 배포 측정에서 모델 요청 duration 합계는 전신 경로 약 1.25초, 손목 경로 약 1.44초였다. 네트워크 왕복 지연이 누적된다.
3. 배포 모델과 해시 JS의 HTTP 응답은 `Cache-Control: public, max-age=0, must-revalidate`. CDN HIT여도 브라우저는 서버 재확인이 필요하다. 캐시된 이동에서도 43개 모델 요청이 관찰됐다. 재다운로드와 재검증은 다르며, 모든 이동에서 18MB를 다시 전송한다고 해석하면 안 된다.
4. 수면 화면은 전용 최소 모델 대신 전체 AnatomyScene을 사용한다. 기본 43개 파일의 gzip 크기는 총 17.93MB. 근육 8.04MB, 신경 3.75MB, 순환계 2.88MB, 피부 1.70MB, 장기 0.82MB, 골격 0.74MB. 신경계는 opacity 0인데도 5개 파일 로딩과 초기 자원 준비가 수행된다. 피부는 패치 위치 계산에 필요하므로 단순히 제거해서는 안 된다.
5. `lib/body-packed.ts`: 디코딩과 bounding box 계산은 주 스레드에서 수행한다. `lib/sleep/patch-surface.ts`는 모델 완료 후 피부 삼각형을 순회한다. 이번 목적지 측정에서는 50ms 이상의 long task가 없었지만 저사양 장치에서 같은 결과를 보장하지 않는다.
6. 성능 모드는 렌더링 품질/프레임 예산/상세 LOD를 조절한다. 기본 43개 파일의 초기 로딩 목록을 줄이지 않으므로 저사양 모드만으로 네트워크 병목이 해결되지 않는다.

## 권장 적용 순서

1. 해시 모델 파일과 해시 JS/CSS에 장기 immutable 브라우저 캐시를 적용하고 실제 배포 응답으로 검증한다. 변경 가능한 manifest 및 HTML은 재검증 유지. 반복 진입의 불필요한 왕복을 줄이는 가장 작은 수정이다.
2. 모델 다운로드를 4~6개 제한 동시 요청으로 변경하되 피부 선행 의존성, abort, 오류 처리, 메모리 상한을 유지한다. 디코딩과 GPU 업로드를 한꺼번에 몰지 않는다.
3. 수면용 로딩 프로필: 신경계 지연/제외, 화면·패치·자세 지지에 필요한 조직 우선 로딩. 전신 실루엣과 패치 계산용 피부를 유지한다.
4. 워커 디코딩 및 점진적 GPU 준비, 패치용 흉부 표면 사전 추출을 검토한다. 저사양 장치에서 CPU trace로 우선순위를 결정한다.
5. 페이지 수명 주기 안전성을 검증한 뒤 공통 shell 유지 및 client navigation을 검토한다. 링크만 교체하는 것은 피한다.

## 재현

`scripts/profiling/sleep-navigation-profile.mjs` 실행. `SOMA_TEST_URL`은 기본 localhost:3000, `SOMA_FROM`은 쉼표로 구분한 출발 경로, `CHROME_PATH`는 브라우저 경로다. 결과는 `outputs/sleep-navigation-profile.json`. outputs는 추적하지 않는다. 현재 측정은 소수 표본이며 수치 개선 보장은 하지 않는다.

## 개선 적용

- 해시 모델 및 `/_next/static/`에 1년 immutable 캐시. manifest는 재검증 유지.
- 최대 4개 단위 병렬 다운로드, manifest 순서대로 디코딩 및 메시 준비. abort/실패 시 남은 요청 취소.
- 수면 전용 프로필에서 비표시 신경계 5개와 신경 보정 GPU 자원 초기화 제외. 피부·골격·근육·장기·혈관 유지. 초기 모델은 38개, 약 14.18MB(약 21% 감소).
- 형상·리깅 변경 없이 모델 재생성 완료. 타입 검사 및 전체 155개 테스트 통과.
- 별도 재현 스크립트로 로컬 production build 전환을 검증한다. 배포 완료 후 네트워크 환경에 따른 실제 체감 차이는 있을 수 있다.

로컬 재측정: 전신→수면 0.34초(기존 0.52초), 손목→수면 0.35초(기존 0.47초). 두 경로 모두 모델 38개는 브라우저 캐시에서 공급되어 모델 전송량 0바이트. 로컬 표본 수치이며 배포 사이트의 시간 보장이 아니다.
